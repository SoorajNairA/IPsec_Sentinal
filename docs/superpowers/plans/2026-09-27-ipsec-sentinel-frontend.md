# IPsec Sentinel Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a polished local React security-forensics interface that renders the real `ipsec-sentinel.analysis/v1` contract, supports genuine guided demos and live PCAP analysis, and makes tunnel, traffic, security, and evidence provenance understandable without implying payload decryption.

**Architecture:** A Vite React/TypeScript SPA consumes an immutable validated analysis object and a separately namespaced ESP X-Ray projection. Genuine demo artifacts are generated from existing real captures, while a narrow loopback-only Python standard-library bridge invokes the existing analyzer for live uploads. Native SVG provides the signature visuals; Radix primitives provide accessible interaction infrastructure; local Playwright drives iterative visual and end-to-end QA.

**Tech Stack:** React, TypeScript, Vite, React Router, Zod, Radix UI primitives, Motion via `motion/react`, Lucide React, custom CSS, Vitest, Testing Library, axe-core, Playwright, Python standard library HTTP server, existing IPsec Sentinel analyzer.

**Spec:** `docs/superpowers/specs/2026-09-27-ipsec-sentinel-frontend-design.md`

## Global Constraints

- Base all work on analyzer commit `64b5884edc9cac3ceea321ce785f36cb24132401`; do not merge, rebase, push, or open a PR automatically.
- Treat `ipsec-sentinel.analysis/v1` version `1.0` as immutable; frontend-only X-Ray data remains in a separate `xray` namespace.
- Never invent findings, algorithms, evidence, packet references, confidence, or decrypted content.
- Every guided demo must be generated by the real analyzer from a genuine existing PCAP and retain a source/digest manifest.
- Traffic confidence must be labeled `Raw / uncalibrated`; the UI must state `Payload visibility: 0%`.
- Bind the live bridge to `127.0.0.1` only, default upload limit `268435456` bytes, and remove temporary uploads on every path.
- Use one icon family, custom graphite visual tokens, native SVG/CSS, and no generic dashboard template, WebGL, large charting package, external runtime font/CDN, telemetry, or remote service.
- Respect `prefers-reduced-motion`, keyboard interaction, visible focus, focus restoration, non-color-only status, and WCAG AA contrast.
- Validate 1440×900, 1280×800, 768×1024, and 390×844 in rendered Chromium.
- Preserve all existing analyzer, dataset, ML, and privileged integration behavior; do not modify the 168-session dataset or retrain the model.

## Review Focus

- A structurally valid-looking but unsupported schema/version must be rejected before render with a safe contract error.
- A capture with thousands of ESP packets must render a deterministic bounded X-Ray without changing analyzer totals or freezing interaction.
- A missing model, insufficient ESP sample, no-IPsec capture, malformed PCAP, and PCAPNG input must each produce an accurate user-facing state without a traceback.
- Evidence references that are absent or contradictory must remain unavailable/unknown rather than resolving to an unrelated record.
- Narrow viewports, keyboard-only use, and reduced motion must retain every critical action and must not leave focus trapped after the evidence drawer closes.
